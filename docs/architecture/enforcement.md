# Строгость: как правила проверяются

Правила проверяет линтер (oxlint через `vp lint`). Нарушение — это ошибка, а не предупреждение.

## Лимит строк

В `.ts` и `.tsx` внутри `src/` не больше **120 строк**. Пустые строки и комментарии не считаются.

Если файл упёрся в лимит, сущность декомпозируется:

- компонент разбивается на дочерние компоненты;
- логика презентера выносится во вспомогательные хуки и утилиты в той же папке.

## Плагин `simple-architecture`

Локальный плагин лежит в `tools/lint/simple-architecture/`.

| Правило                | Автофикс | Что проверяет                                                                                                            |
| ---------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| `file-naming`          | нет      | `X.tsx` лежит в папке `X/`; презентер называется `use<X>Presenter.ts`, типы — `X.types.ts`                               |
| `presenter-usage`      | нет      | презентер импортирует только его компонент из той же папки                                                               |
| `pure-view`            | нет      | в теле компонента только вызов презентера с деструктуризацией, ранний `return` и JSX; нет инлайн-стрелок в атрибутах JSX |
| `encapsulated-imports` | да       | снаружи папки компонента импорт только через barrel; `@/components/ui/*` — только из `src/components/<Name>/`            |

Автофикс `encapsulated-imports`:

- импорт мимо barrel (`…/Name/Name`, `…/Name/Name.types`) заменяется импортом папки, если её `index.ts` экспортирует все импортируемые имена;
- импорт shadcn-примитива (`@/components/ui/x`) заменяется импортом обёртки `@/components/<Name>` для каждого имени, если обёртка есть.

Остальные правила требуют рефакторинга, а не механической замены: переименовать файл или перенести логику в презентер линтер не может.

Автофиксы применяются командой `pnpm lint:fix`, хуком Claude после каждой правки и в VS Code при сохранении (`source.fixAll.oxc`).

## Прочие правила

- Только именованные экспорты (`import/no-default-export`).
- Компоненты — стрелочные функции.
- `import type` для типов, запрет `any`, без циклических импортов.

## Генератор

Структура компонента создаётся детерминированно скриптом, а не вручную:

```sh
pnpm gen:component <путь> [--presenter] [--props] [--styles] [--test] [--wrap <ui-файл>]
```

Подробности — в `.claude/skills/create-component/SKILL.md`.
