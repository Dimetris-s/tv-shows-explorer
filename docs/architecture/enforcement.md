# Строгость: как правила проверяются

Правила проверяет линтер (oxlint через `vp lint`). Нарушение — это ошибка, а не предупреждение.

## Лимит строк

В `.ts` и `.tsx` внутри `src/` и `server/src/` не больше **120 строк**. Пустые строки и комментарии не считаются.

Если файл упёрся в лимит, сущность декомпозируется:

- компонент разбивается на дочерние компоненты;
- логика презентера выносится во вспомогательные хуки и хелперы в `logic/`;
- таска становится папкой и разбивается на части.

## Плагин `simple-architecture`

Локальный плагин лежит в `tools/lint/simple-architecture/`.

| Правило                | Автофикс | Что проверяет                                                                                                                                                                                                                          |
| ---------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `file-naming`          | нет      | `X.tsx` лежит в папке `X/`; презентер — `X/logic/use<X>Presenter.ts`, типы — `X.types.ts`; служебные папки строчными                                                                                                                   |
| `presenter-usage`      | нет      | презентер импортирует только его компонент из той же папки                                                                                                                                                                             |
| `pure-view`            | нет      | в теле компонента только вызов презентера с деструктуризацией, ранний `return` и JSX; нет инлайн-стрелок в атрибутах JSX                                                                                                               |
| `encapsulated-imports` | да       | снаружи папки компонента импорт только через barrel; `@/components/ui/*` — только из `src/components/<Name>/`                                                                                                                          |
| `logic-scope`          | нет      | `X/logic/` импортирует только `X`; `X/tasks/`, `X/types/`, `X/components/` — только поддерево `X/`; View не импортирует таски и из `logic/` берёт только презентер                                                                     |
| `framework-free-tasks` | нет      | в `tasks/` нет импортов React, компонентов, `.tsx` и хуков                                                                                                                                                                             |
| `task-shape`           | нет      | таска — `.ts` с одним экспортом-функцией с именем файла в camelCase; `index.ts` папки таски — только реэкспорт; у `tasks/` нет barrel                                                                                                  |
| `server-boundary`      | нет      | фронт импортирует из сервера только `@tv/server/contract` и только `import type`; относительные пути в `server/` запрещены                                                                                                             |
| `server-layers`        | нет      | серверные роуты не импортируют `stores/` и `services/` (только таски и контракт); таски не импортируют роуты, `hono` и `zod`; `stores/`, `types/` и `contract/` не импортируют внешние слои (`stores/` и `types/` — и `contract/`)     |
| `front-layers`         | нет      | направление слоёв фронта: `types/`, `lib/`, `services/` не знают приложения; `stores/` не импортирует таски, сервисы, хуки и компоненты; `src/tasks/` — компоненты и хуки; View (`.tsx`) не импортирует `stores/`, `services/` и таски |

Вне плагина: `no-restricted-imports` запрещает `wouter` везде в `src/`, кроме адаптера `src/services/router/`.

На сервере (`server/src/**`) действуют лимит строк, именованные экспорты, `task-shape`, `framework-free-tasks` (для `tasks/`) и `server-layers`. Правила компонентов и презентеров там не применяются: View на сервере нет.

Автофикс `encapsulated-imports`:

- импорт мимо barrel (`…/Name/Name`, `…/Name/Name.types`) заменяется импортом папки, если её `index.ts` экспортирует все импортируемые имена;
- импорт shadcn-примитива (`@/components/ui/x`) заменяется импортом обёртки `@/components/<Name>` для каждого имени, если обёртка есть.

Глагольность имени таски линтер не проверяет: это остаётся на совести автора.

Остальные правила требуют рефакторинга, а не механической замены: переименовать файл или перенести логику в презентер линтер не может.

Автофиксы применяются командой `pnpm lint:fix`, хуком Claude после каждой правки и в VS Code при сохранении (`source.fixAll.oxc`).

## Прочие правила

- Только именованные экспорты (`import/no-default-export`).
- Компоненты — стрелочные функции.
- `import type` для типов, запрет `any`, без циклических импортов.

## Генератор

Структура компонента создаётся детерминированно скриптом, а не вручную:

```sh
pnpm gen:component <путь> [--presenter] [--props] [--styles] [--test] [--wrap <ui-файл>]
```

Подробности — в `.claude/skills/create-component/SKILL.md`. Флаг `--presenter` создаёт `logic/use<Name>Presenter.ts`.

Таски создаются так же:

```sh
pnpm gen:task <путь до tasks>/<verbName> [--folder]
```

Генератор проверяет, что путь лежит прямо в `tasks/` компонента (`<Name>/logic/tasks`, `<Widget>/tasks`), в `src/tasks` или в `server/src/tasks`, а имя — camelCase и не хук. Подробности — в `.claude/skills/create-task/SKILL.md`.
