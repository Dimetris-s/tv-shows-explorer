# Структура папок и декомпозиция

## Компонент — это папка

```
ShowCard/
  ShowCard.tsx                # View: всегда есть
  index.ts                    # barrel: всегда есть
  ShowCard.types.ts           # пропсы: если компонент их принимает
  ShowCard.module.css         # стили: только если не хватает Tailwind
  ShowCard.test.tsx           # тесты: только если пишем тесты
  skeletons.ts                # статические данные для JSX
  logic/                      # JS/TS без отображения: если есть логика
    useShowCardPresenter.ts   # Presenter
    formatShow.ts             # хелперы и вспомогательные хуки презентера
    tasks/                    # таски этого компонента (docs/architecture/tasks.md)
      countGenres.ts
```

**Создаём только то, что нужно.** Нет стилей — нет файла стилей. Не пишем тесты — нет тест-файла. Нечего готовить — нет презентера и папки `logic/`.

Имена файлов повторяют имя компонента: `ShowCard.tsx`, `ShowCard.types.ts`, `use<ShowCard>Presenter.ts`. Папка компонента называется в PascalCase, служебные папки (`logic/`, `tasks/`, `components/`) — строчными.

## Папка `logic/`

В `logic/` лежит всё, что не является отображением: презентер, его хелперы и вспомогательные хуки, папка `tasks/` с тасками. Тип пропсов `Name.types.ts` остаётся в корне компонента: он общий для View и презентера.

`logic/` приватна: её файлы импортирует только сам компонент (`Name.tsx` и другие файлы его `logic/`). Дочерние компоненты в `logic/` родителя не ходят. Если ребёнку понадобилась таска родителя, она переезжает в `tasks/` уровнем выше (см. «Переиспользование»).

## Barrel

В каждой папке компонента лежит `index.ts`, который экспортирует компонент и его типы. Снаружи папки компонент импортируется только через barrel:

```ts
import { ShowCard } from '@/app/ShowList/ShowCard'; // ✅
import { ShowCard } from '@/app/ShowList/ShowCard/ShowCard'; // ❌ импорт мимо barrel
```

## Декомпозиция

Если компонент состоит из других компонентов, дочерние компоненты лежат папками **внутри папки родителя** и устроены по тем же правилам:

```
ShowList/
  ShowList.tsx
  useShowListPresenter.ts
  index.ts
  ShowCard/
    ShowCard.tsx
    index.ts
```

## Переиспользование

- `src/components/` — компоненты, которые **уже** переиспользуются в разных частях приложения.
  - Исключение — базовые элементы UI kit (кнопка, поле ввода, бейдж, скелетон, чипс): они почти наверняка будут переиспользоваться, поэтому кладутся сюда сразу.
  - Всё остальное (пагинация, поле поиска, карточка) сначала живёт в папке фичи или экрана, где используется. В `src/components/` компонент переезжает, когда появляется второе место использования.
- Если компонент переиспользуется только внутри одного крупного компонента (виджета) в разных его частях, на уровне этого виджета создаётся своя папка `components/`:

```
ShowSearch/
  ShowSearch.tsx
  components/
    GenreChip/          # используется и в Filters, и в ShowList
  Filters/
  ShowList/
```

Остальное переиспользуемое выносится по той же схеме, когда появляется второе место использования:

| Что   | Только у одного компонента | Несколько частей одного виджета | Разные части приложения |
| ----- | -------------------------- | ------------------------------- | ----------------------- |
| Таски | `Name/logic/tasks/`        | `<Widget>/tasks/`               | `src/tasks/`            |
| Хуки  | `Name/logic/`              | —                               | `src/hooks/`            |
| Типы  | рядом с потребителем       | `<Widget>/types/`               | `src/types/`            |

- Хуки не бывают уровня виджета: если хук нужен второму компоненту, он сразу переезжает в `src/hooks/`.
- `X/tasks/` и `X/types/` видны всему поддереву `X/`. У папок `tasks/` нет barrel: таска импортируется напрямую (`@/tasks/searchShows`).

## Верхний уровень `src/`

```
src/
  main.tsx        # точка входа: монтирует App
  index.css       # токены дизайн-системы и Tailwind
  app/            # компонент App; дальше вся иерархия приложения
  components/     # UI kit и компоненты, которые уже переиспользуются
    ui/           # shadcn-примитивы — вендорный код
  tasks/          # таски, которые уже переиспользуются в разных частях приложения
  hooks/          # хуки, которые уже переиспользуются
  types/          # типы, которые уже переиспользуются
  services/       # инфраструктура: http-клиент, временно useQuery и конфиг TVmaze
  lib/            # общие утилиты (cn и т. п.)

Папки `tasks/`, `hooks/` и `types/` создаются, когда в них появляется первый файл.
```

Папка `app/` — это папка компонента `App` (`app/App.tsx`, `app/logic/useAppPresenter.ts`). Это единственное исключение из правила «папка называется как компонент», потому что `app` одновременно является корнем иерархии приложения.

## shadcn/ui

`src/components/ui/` — вендорный код: его генерирует CLI shadcn, и мы правим его только для подгонки под дизайн-систему. Архитектурные правила и лимит строк на эту папку не распространяются.

Импортировать `@/components/ui/*` можно **только из обёрток** в `src/components/<Name>/`. Остальное приложение работает только с нашими компонентами (`@/components/Button`), а вендор изолирован за обёрткой, как внешний сервис за адаптером.
