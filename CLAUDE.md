# TV Shows Explorer

Учебный проект для отработки архитектуры **Simple Architecture** (Clean Architecture + VIPER, перенесённые на React). SPA для поиска сериалов через API TVmaze. Без SSR.

## Стек

- Vite+ (`vp`): Vite, Oxlint (type-aware), Oxfmt, Vitest
- React 19, TypeScript 7 (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`)
- Tailwind CSS v4, shadcn/ui на Base UI, дизайн-система Cinema Noir (`docs/design-system.md`)
- pnpm, Node ≥ 24.11

## Команды

- `pnpm dev`: dev-сервер
- `pnpm check`: формат, линт и типы. Запускай перед тем, как считать задачу выполненной.
- `pnpm build`: сборка
- `pnpm gen:component <путь> [флаги]`: создать компонент (см. ниже)

После каждой правки файла хук `.claude/hooks/lint-changed-file.sh` форматирует его и линтит. Ошибки из хука исправляй сразу.

## Архитектура: главное

Полный конспект: `docs/architecture/`. Подробные правила подгружаются из `.claude/rules/` при работе с файлами в `src/`.

1. **Компонент — это только View**: вызов `use<Name>Presenter` с деструктуризацией, ранний `return` и JSX (`map`, условный рендеринг, инлайновые классы). Никаких хуков, вычислений и инлайн-стрелок.
2. **Презентер готовит всё**: данные, флаги, готовые обработчики или фабрики обработчиков. Возвращает один объект. Пропсы презентера совпадают с пропсами компонента (`<Name>.types.ts`).
3. **Компонент — это папка** `Name/` с `Name.tsx` и `index.ts`, остальные файлы только по необходимости. Дочерние компоненты лежат папками внутри родителя.
4. **Не больше 120 строк** в `.ts`/`.tsx` в `src/`. Упёрся в лимит — декомпозируй.
5. **Только именованные экспорты**, компоненты — стрелочные функции, импорт компонента снаружи только через barrel.
6. **shadcn (`src/components/ui`) — вендорный код.** Его импортируют только обёртки в `src/components/<Name>/`.
7. **В `src/components/` компонент попадает, только когда переиспользуется.** Сразу туда кладутся лишь базовые элементы UI kit (кнопка, поле ввода, бейдж, скелетон, чипс). Всё остальное живёт в папке фичи или экрана, где используется, и переезжает в `src/components/` при втором месте использования.

## Комментарии

Комментарии в коде не пишем. Код должен быть понятен из имён и структуры, без пояснений. Встретил комментарий — удали. Комментарий допустим, только если пользователь сам указал место и попросил его написать. Директивы инструментов (`oxlint-disable-next-line`) — не комментарии, но без текстового обоснования.

## Как работать

- **Вёрстка** — только токены дизайн-системы (`bg-primary`, `text-muted-foreground`, `text-h1`, `rounded-md`), без произвольных цветов и размеров. Текст — через компонент `Typography`. Таблица токенов и компонентов: `docs/design-system.md`. Сначала ищи готовый компонент в `src/components/`.
- **Новый компонент** — только через генератор, не вручную. Перед созданием вызови скилл `create-component`.
- **Файл превысил 120 строк** или компонент разросся — вызови скилл `decompose-component`.
- **Новый shadcn-примитив**: `pnpm dlx shadcn@latest add <name>`, затем обёртка `pnpm gen:component src/components/<Name> --wrap <name>`.
- Правила проверяет линтер (`tools/lint/simple-architecture/`). Если правило мешает, не отключай его комментарием, а обсуди с пользователем.
- Архитектурные правила пополняются по мере прохождения курса. Новые решения пользователя записывай в `docs/architecture/` и, если нужно, в `.claude/rules/`.
