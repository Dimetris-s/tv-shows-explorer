# Декомпозиция

Лимит в 120 строк — сигнал, что сущность делает слишком много. Его не обходят: не сжимают код, не выносят куски в «utils.ts» без смысла и не отключают правило.

## Компонент (`Name.tsx`) — режь JSX на дочерние компоненты

1. Найди в JSX самостоятельные смысловые блоки: шапку, список, элемент списка, фильтры, пустое состояние.
2. Каждый блок станет дочерним компонентом. Создай его через скилл `create-component` по пути `<папка Name>/<Child>`.
3. Если блок нужен в нескольких дочерних компонентах одного родителя, положи его в `<папка Name>/components/<Child>`. Если он нужен всему приложению — в `src/components/<Child>`.
4. Перенеси в дочерний компонент JSX, а в его презентер — относящуюся к нему логику. Родитель передаёт только нужные пропсы.

## Презентер (`logic/useNamePresenter.ts`) — режь по ответственности

1. Сгруппируй, что делает презентер: загрузка данных, бизнес-правила, пагинация, обработчики.
2. Бизнес-логику (запросы, правила из спеки) вынеси в таски: скилл `create-task`, путь `logic/tasks/<verb>`.
3. Самостоятельную группу с состоянием вынеси во вспомогательный хук в `logic/` (`useNamePagination.ts`), а UI-вычисления (форматирование, подписи) — в хелпер там же (`formatShow.ts`).
4. Презентер собирает результат хуков и тасок в один объект для View.
5. Если логика относится только к одной части JSX, её место, скорее всего, в презентере дочернего компонента: сначала декомпозируй View.

## Таска — делай папкой

1. Преврати файл `tasks/verb.ts` в папку `tasks/verb/`: `verb.ts` — точка входа, `index.ts` — только `export { verb } from './verb';`.
2. Самостоятельные шаги вынеси в соседние файлы папки. Шаг, нужный другим таскам, — отдельная таска.

## После

- Проверь, что каждый файл стал меньше лимита и у каждого одна ответственность.
- Импорт дочерних компонентов — через barrel (`./Child`).
- Запусти `pnpm check`.
