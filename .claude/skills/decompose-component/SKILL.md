# Декомпозиция

Лимит в 120 строк — сигнал, что сущность делает слишком много. Его не обходят: не сжимают код, не выносят куски в «utils.ts» без смысла и не отключают правило.

## Компонент (`Name.tsx`) — режь JSX на дочерние компоненты

1. Найди в JSX самостоятельные смысловые блоки: шапку, список, элемент списка, фильтры, пустое состояние.
2. Каждый блок станет дочерним компонентом. Создай его через скилл `create-component` по пути `<папка Name>/<Child>`.
3. Если блок нужен в нескольких дочерних компонентах одного родителя, положи его в `<папка Name>/components/<Child>`. Если он нужен всему приложению — в `src/components/<Child>`.
4. Перенеси в дочерний компонент JSX, а в его презентер — относящуюся к нему логику. Родитель передаёт только нужные пропсы.

## Презентер (`useNamePresenter.ts`) — режь по ответственности

1. Сгруппируй, что делает презентер: загрузка данных, фильтрация, пагинация, обработчики.
2. Самостоятельную группу с состоянием вынеси во вспомогательный хук в той же папке (`useNamePagination.ts`), а чистые вычисления — в утилиту (`filterShowsByGenre.ts`).
3. Презентер собирает результат вспомогательных хуков в один объект для View.
4. Если логика относится только к одной части JSX, её место, скорее всего, в презентере дочернего компонента: сначала декомпозируй View.

## После

- Проверь, что каждый файл стал меньше лимита и у каждого одна ответственность.
- Импорт дочерних компонентов — через barrel (`./Child`).
- Запусти `pnpm check`.
