# Создание таски

Правила: `.claude/rules/tasks.md`, мотивация: `docs/architecture/tasks.md`.

## 1. Это точно таска?

Таска — шаг, который описывается в спеке без слов «экран», «кнопка», «страница»: запрос к API, бизнес-правило, вычисление над данными предметной области. Подписи, форматирование для UI, выбор состояния экрана, пагинация и навигация — это презентер и его хелперы в `logic/`, не таска.

## 2. Выбери имя и место

Имя — глагол в camelCase: `searchShows`, `filterShowsByGenre`, `countGenres`.

| Кто вызывает                         | Путь                        |
| ------------------------------------ | --------------------------- |
| презентер одного компонента          | `<Name>/logic/tasks/<verb>` |
| презентеры нескольких частей виджета | `<Widget>/tasks/<verb>`     |
| разные части приложения              | `src/tasks/<verb>`          |

Сначала таска живёт в `logic/tasks/` компонента. Переезжает выше, только когда появляется второй потребитель. Если не очевидно, куда положить, спроси пользователя.

## 3. Запусти

```sh
pnpm gen:task src/app/ShowSearch/logic/tasks/searchShows
pnpm gen:task src/tasks/searchShows --folder   # таска-папка: части в соседних файлах
```

`--folder` нужен, когда таска не помещается в 120 строк: `verb/verb.ts` — точка входа, `verb/index.ts` — только реэкспорт, остальные файлы папки — части таски.

## 4. Наполни

- Замени заглушку `throw new Error(...)` реализацией. Можно `async`, можно принимать `AbortSignal`.
- Без React: никаких `react*`, хуков, компонентов. Сеть — через `httpGet` из `@/services/http`, сторы — напрямую.
- Запрос к API переводит DTO в свой тип; DTO дальше таски не уходят.
- В файле таски один экспорт-функция с именем файла; типы экспортировать можно.
- Вызывай таску из презентера (или другой таски). Навигацию после неё делает презентер.
- Переезд таски на уровень выше: перенеси файл (`git mv`) и поправь импорты.
- В конце запусти `pnpm check`.
