# Tasks

Мотивация и примеры: `docs/architecture/tasks.md`, направление зависимостей: `docs/architecture/dependencies.md`.

- Таска — обычная (можно `async`) функция, реализующая бизнес-логику: шаг, который описывается в спеке без слов «экран», «кнопка», «страница».
- Имя — глагол в camelCase: `searchShows`, `filterShowsByGenre`. Файл называется как функция.
- Один файл — один именованный экспорт таски. Большая таска — папка `verbName/` с `verbName.ts` и частями; её `index.ts` содержит только `export { verbName } from './verbName';`.
- Без React: не импортируй `react*`, хуки, компоненты, `.tsx`, презентеры. Побочные эффекты разрешены: http-клиент, сторы напрямую (без thunk/saga), `AbortSignal`.
- Правило, общее для всех клиентов (фильтрация, пагинация, избранное), — серверная таска (`server/src/tasks/`). Клиентская таска вызывает наш API, обновляет стор, откатывает оптимистичные изменения.
- Сеть на фронте — только `httpGet`/`httpPost`/`httpPut`/`httpDelete` из `@/services/http` в наш `/api`. Типы ответа — из `@tv/server/contract`. Отдельного API-слоя нет.
- Внешние API (TVmaze) — только серверные таски; DTO переводятся в свой тип на границе таски.
- Сторы фронта — `src/stores/<name>Store.ts`, `createStore` из `zustand/vanilla`. Таска пишет `store.setState`, презентер читает `useStore(store, selector)`. View стор не импортирует.
- Интерфейс таски описывает вариант использования, а не экран: принимает минимум нужного (`toggleFavorite({ id, isFavorite })`, а не весь объект по необходимости), возвращает данные предметной области. Подписи, флаги и состояния экрана готовит презентер. Проверка: другой клиент вызвал бы таску как есть?
- Данные одного экрана таска возвращает, а не кладёт в стор. В стор — только глобальное (нужно в нескольких несвязанных местах). Перед новым полем стора спроси: можно ли держать это в презентере?
- Стор — только состояние и селекторы. Устройство полей знают селекторы рядом со стором (`selectIsFavorite(state, show)`); таски и презентеры читают через них, а не через `state.field[…]`.
- Ответ API типизируется типом контракта. Свой тип и маппер — в таске, только когда форма ответа разошлась с нуждами фронта. Заранее типы не дублируй.
- Вызывают таску презентер, его хуки или другие таски. Не View.
- Навигацию в таске не делай: это работа презентера.
- Место: `Name/logic/tasks/` (один компонент) → `<Widget>/tasks/` (несколько частей виджета) → `src/tasks/` (всё приложение). Переезд — при втором месте использования.
- Новая таска создаётся генератором (скилл `create-task`).
